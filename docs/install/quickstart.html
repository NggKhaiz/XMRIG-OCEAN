Install in one command

curl -fsSL https://raw.githubusercontent.com/NggKhaiz/ZMRIG/BETA/oneclick.sh \
  | sudo bash -s -- --wallet 4YourMoneroAddress

If the repository is already cloned:

sudo ./oneclick.sh --wallet 4YourMoneroAddress

That is the whole install. It installs the build dependencies, compiles the hash engine and the miner, measures the machine to pick a thread count, tunes the host, writes /etc/zmrig/config.json, creates zmrig.service, runs a self-check, and prints the hashrate it measured. Re-running is safe: no duplicate services, no overwritten config without --force, no rebuild when the binary is newer than the sources.

What it decides, and why​

DecisionHow the installer chooses
Enginezmrig (0 % fee). It advertises the whole RandomX family, so a switching pool can still move the rig to whichever coin pays best. --algo outside RandomX, or --engine=xmrig, selects the C++ engine.
Profilefree (maximum hashrate) everywhere, except a laptop on battery → watt (maximum hashes per watt).
ThreadsMeasured after the build: each candidate runs 8 s on the real dataset, the winner is written to the config.
Huge pagesSized from the dataset. If the kernel grants fewer, it falls back to transparent huge pages and says so.
Governorperformance for free, the existing powersave governor for watt.

See the same list without touching the machine:

./oneclick.sh plan
==> plan
    engine         zmrig  (RandomX family, 0% fee)
    pool           gulf.moneroocean.stream:10001
    algo           auto  (RandomX family: rx/0, rx/wow, rx/arq, …)
    profile        free  (auto: no battery, electricity is treated as free)
    mode           auto (fast when RAM allows)
    huge pages     none yet, the installer reserves what the dataset needs
    autotune       8 s per candidate, winner written to config.json
    service        zmrig.service (systemd)

Verify it worked​

sudo ./oneclick.sh status      # service, hashrate 10s/60s/15m, shares, huge pages
sudo ./oneclick.sh verify      # prove the 0 % fee
sudo ./oneclick.sh logs 50     # last 50 log lines
==> verifying zmrig
    OK  PASS rx/0 reference vector
    OK  PASS pipelined hashing
    OK  PASS full-memory dataset matches the cache
    OK  no donation endpoints or wallets: 0% developer fee
    OK  verified

status only reports measured numbers: a miner that started a moment ago says warming up instead of quoting the previous run, because the dataset takes 15–25 seconds to build.

The two power profiles​

# free electricity: café, school, an office machine — maximum hashrate
sudo ./oneclick.sh install --wallet 4YourMoneroAddress --profile free

# every watt costs money: laptop, metered VPS — maximum hashes per watt
sudo ./oneclick.sh install --wallet 4YourMoneroAddress --profile watt

free uses every logical CPU, --mode fast, huge pages and --priority 5. watt drops to one thread per physical core (SMT adds 5–15 % hashrate for 30–40 % more power), does not pin the CPU to its highest clock, and stops by itself when a laptop switches to battery.

Update, remove​

sudo ./oneclick.sh update        # git pull, rebuild, restart
sudo ./oneclick.sh uninstall     # stop, remove service and binary, keep the config
sudo ./oneclick.sh purge --dry-run
sudo ./oneclick.sh purge         # remove everything the tool created

purge prints every path it created with its size, requires the word purge to confirm, resets vm.nr_hugepages to 0, and never touches a file it did not make. --dry-run lists without deleting.

If something is wrong​

  • No huge pages. In a container or an OpenVZ VPS the kernel may refuse; the miner logs the shortfall and continues at roughly 78 % hashrate. Nothing to fix — ask the host for 2 MiB pages.
  • Service restarts in a loop. Almost always a config the miner rejects. Run sudo journalctl -u zmrig -n 60 and look for the first line after the binary starts; the installer validates the config before writing it, so this usually means someone edited it.
  • the miner rejected the generated config. The wallet contains a character that is not valid base58. Re-run with a clean address.

The rest of the failure modes are in Troubleshooting.
