Command builder

Every switch below maps to one flag. What you see is exactly what the installer receives — nothing is added later.

Wallet address

Not entered yet.

Shown on the pool dashboard to tell machines apart.

Pool

Pays the most per hash: the pool moves the rig to whichever RandomX coin is paying best and settles in XMR. Needs --algo=auto, which is the default. gulf.moneroocean.stream:10001

Backup pools

Used only when the primary cannot be reached or refuses this IP. Pick a different operator.

Engine

Switching pool → C++ engine. RandomX-only pool → zmrig.

NetworkDial a different address (--connect-to)

host:port. Keeps the pool's hostname for SNI and the Host header, which is how a filtered DNS name is worked around. Leave it empty unless the name does not resolve here.

Your command

curl -fsSL https://raw.githubusercontent.com/NggKhaiz/ZMRIG/BETA/oneclick.sh \
  | sudo bash -s -- install --wallet YOUR_WALLET --pool gulf.moneroocean.stream:10001 --yes

Paste a wallet address to get a command.

After the install

# service state and log — needed for any debugging
sudo systemctl status zmrig --no-pager -l
sudo journalctl -u zmrig -n 40 --no-pager

# measure the machine and print a code for the calculator
sudo ./oneclick.sh report --power 0

Remove it again

# look before deleting
sudo ./oneclick.sh purge --dry-run
sudo ./oneclick.sh purge

The same command, with plan

curl -fsSL https://raw.githubusercontent.com/NggKhaiz/ZMRIG/BETA/oneclick.sh \
  | sudo bash -s -- plan --pool gulf.moneroocean.stream:10001

Resolves the pool, the engine, the profile, the huge pages and the thread search, prints all of it, and writes nothing.

What each switch turns into​

You chooseThe installer receives
Wallet--wallet <address>
Rig name--rig-id <name>
Pool--pool <host:port> or --pool tls://<host:port>
Backup pools--failover <host:port>,<host:port>
Fixed engine--engine zmrig or --engine xmrig (absent = automatic)
Fixed profile--profile free or --profile watt (absent = automatic)
443-only network--cloudflare --ws-path <path>
Proxy--proxy <url>
Pool name filtered here--connect-to <host:port>
Host refuses MSR writes--no-msr
Rented hash--nicehash
Do not tune the host--no-tune
No thread search--no-autotune
Keep the config(no --force)

Two rules are worth knowing because they change the command rather than just adding a flag:

  • Asking for WebSocket or a proxy forces --engine zmrig. The C++ engine has no WebSocket client and no proxy support, so the alternative would be a config nothing can run.
  • A TLS pool becomes part of the --pool value (tls://host:port), because that is the form oneclick.sh parses.

The address you type is validated before the copy button unlocks: 95 characters for a standard Monero address, 106 for an integrated one, base58 alphabet only. A pool host is validated as host:port, and a full stratum+tcp://… URL pasted from a provider page is accepted.

The proxy field wants the whole URL — socks5://host:port or http://user:pass@host:port — because that is what the miner parses. The dial address is host:port only; it replaces the resolved IP but keeps the pool's hostname in SNI and the Host header, which is the point: a name blocked by a local resolver still works if you know where it lives.

Preview first​

The preview button copies the same command with plan in place of install. plan resolves the pool, the engine, the profile, the huge-page strategy and the autotune plan, prints them, and stops. It writes nothing.

Neither command contains your wallet's private anything: a public address is the only credential involved, and it is visible to the pool by design.
