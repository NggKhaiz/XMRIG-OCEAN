Choosing an engine

Both engines compile to the same hash loop: zmrig/capi binds the C++ RandomX implementation into the Zig binary, so the numbers are the same within noise. The difference is everything around the loop.

xmrig (C++)zmrig (Zig)
Algorithmsall of them (34+)the RandomX family: rx/0, rx/2, rx/wow, rx/arq, rx/graft, rx/sfx, rx/yada, panthera
TransportsTCP, TLSTCP, TLS, ws, wss
Proxypartial SOCKS5HTTP CONNECT and SOCKS5, with auth and remote DNS
Monitoring APIyes, completeyes, read-only, XMRig-compatible shape
Report code for the calculatornoyes (--report)
Health watchdognoyes, restarts when earnings stop
Measured rx/01075 H/s1008–1103 H/s, same host, same config

Both are measured on the same 2 vCPU machine; the spread is the host, not the engine. Benchmarks has the method.

Which one​

  • RandomX on a normal VPS: either. zmrig is smaller, has the transport options and prints a report code, so it is what the installer picks.
  • A switching pool (MoneroOcean and clones): zmrig still works — it advertises the whole RandomX family and the pool moves the rig between coins. It cannot mine the non-RandomX algorithms those pools also pay for, so a pool that values breadth more than depth is better served by xmrig. The installer's auto setting chooses xmrig for a switching pool for this reason; zmrig remains the 0 %-fee option either way.
  • Any other algorithm (cn/heavy, ghostrider, KawPow): xmrig. zmrig refuses at argument-parse time rather than starting and failing to connect.
  • A network that only allows 443, or a proxy: zmrig. See Networks that only allow 443.

Switching engines​

The engine is recorded in /etc/zmrig/engine, so later subcommands (status, logs, bench, …) use the same binary without repeating --engine.

sudo ./oneclick.sh install --wallet 4YourMoneroAddress --engine zmrig --force
sudo ./oneclick.sh install --wallet 4YourMoneroAddress --engine xmrig --force

Both binaries can stay installed side by side; the service runs whichever the marker names.
